## Root cause and original decision checkpoint

The approved model permits one engineer to submit distinct area slips. The actual legacy unique index permits only one per engineer/day, and the implementation plan omitted its transition. Earlier preflight was incomplete; this is not a reason to revise the approved business model.

Do not drop the global index or infer historical area data. At the original checkpoint this scoped extension was **not yet implemented/approved**:

1. Add an explicit source-format marker: existing and legacy-created rows remain v1; only checked WBS v2 creation assigns v2. Prevent browser clients from choosing/changing the marker.
2. Replace the global day/author uniqueness with equivalent uniqueness for v1 rows only. New v2 area creation remains serialized and rejects an existing same actor/scope/date/area; no new area uniqueness constraint on historical rows.
3. Constrain the legacy `findMine` lookup to v1 only, preserving its single-row behavior. Keep legacy payload/workflow unchanged and preserve historical rows/IDs/content/resources/status.
4. Extend non-admin Cloud smoke to prove A+B works, duplicate area/command spoof denied, legacy duplicate day still denied, direct marker spoof denied, and old lookup remains unambiguous. Review migration and all existing compatibility gates before application.

This touched a shared legacy constraint and one legacy lookup beyond the original Task 2 file map. Execution paused for user direction; at that checkpoint no Task 2 completion/commit or persistent Cloud apply had occurred.
